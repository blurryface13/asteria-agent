## 运行与评分怎样配合

采用“执行时采集、结束后独立评分、历史产物可补评”，不是把裁判串进研究的每个动作里。

1. 研究运行保存任务输入、代码/模型/提示词/Skill 版本、动作与工具观察、来源快照、最终产物哈希、真实 usage。生产充分性审查继续负责研究停止，不兼任独立评测裁判。
2. 用户可手动发起评分；自动评分作为可选策略，在产物完成后入队，可按比例抽样并设置独立费用预算。评分失败不能把已完成研究改成失败。
3. 历史记录若具备输入和报告，可以评内容；若缺原文快照则引用支持率为不可判定，若缺工具轨迹则工具指标不可判定。不能自动重新联网补证据来冒充当时运行快照。
4. **重新评分**复用同一产物，追加新的评分版本；**重跑对比**执行新版本 Agent，会调用工具/模型并产生新费用，两者在界面和 API 上明确区分。
5. 幂等键由 run_id、artifact_hash、scorer_version、评分配置构成。相同产物可有多个 EvalRun；原始结果不覆盖。评分任务保存 queued/running/completed/failed/cancelled，与研究状态独立。

## 参考工作与采用范围

- [Inspect scoring workflow](https://inspect.aisi.org.uk/scoring-workflow.html)：支持生成与评分拆开，以及从既有日志重新评分。采用它的 Dataset/Solver/Scorer 组织与版本化日志；Solver 适配 Asteria 自身运行时，不用另一套 Agent 替代被测系统。
- [AstaBench / Ai2](https://github.com/allenai/asta-bench)：科研场景与工具任务最接近本项目；参考其 Inspect 集成和执行/评分隔离。先审计环境依赖，兼容时复用 dora，确有冲突才隔离评分工具环境。
- [DeepResearch Bench](https://deepresearch-bench.github.io/)：RACE 评报告综合质量，FACT 关注引用。借鉴完整性、深度、指令遵循、可读性与事实引用核验，中文版自建任务标为 Asteria rubric，不冒充官方榜单成绩。
- [LangSmith evaluation types](https://docs.langchain.com/langsmith/evaluation-types)：参考在线与离线评测的职责划分，不要求接入付费服务才能使用本项目。

## 指标与 P99

科研质量主要看必需目标完成、证据支撑覆盖、claim–citation 支持率、引用覆盖、综合分析质量、工具语义正确性，以及无效补研/过早停止。分母、不可判定率与评分证据必须同时保存。失败归因区分模型、工具、环境、人工取消，不从总体端到端失败数中删掉外部故障。

P99 是延迟分布的尾部指标，不是研究质量或自主性指标。[Google SRE 的 SLO 指南](https://sre.google/sre-book/service-level-objectives/)用分位数区分典型与尾部体验。研究任务按任务类型/预算分别报告样本数、平均值、P50/P95、范围；小样本不承诺稳定 P99，也不能平均各批次的 P99。接口负载测试积累足够请求后另报 P99、吞吐、错误率和并发；它与十分钟级调研耗时不能混成一个指标。

拆分排队、人工等待、活跃研究、出版编译和评测耗时。保留失败任务耗时与费用。没有上游 token/usage 则显示缺失，不按字符估算额度。

4. 数据集版本、冻结 split、三次重复和配对消融，BadCase 质检回流开发/回归集。
