已下载的 PDF：`/Users/dora/Downloads/nvda_fy26_fy25_report.pdf`。六页均可渲染，收入、经营现金流、同比表与两张图均出现，正文页码旁有指向 SEC EDGAR HTML 的可点击链接（并非直接跳到 PDF 指定页）。较 Asteria 原冒烟增加了独立 FY2025 文件交叉核对、计算值标识及图表。仍有两个值得关注的质量问题：

本项目之前的一次 NVIDIA 本地冒烟详见 [financial-report-acceptance.md](financial-report-acceptance.md)：Asteria 只读到了 FY2026 原文，用其 FY2025 比较列完成数值对照，正确披露了该限制，但**没有**核对独立 FY2025 年报。两次输入不完全相同；ClawsGO 此次提示明确指定“两份独立原文”，因此当前只比较流程与缺口，不把不同提示下的结果当作模型优劣 A/B。

## Asteria 同指令实测与修复

使用与上方 ClawsGO 相同的公开 NVIDIA 指令，运行 `scripts/smoke-financial-report.py --max-actions 64 --task '…'`。本次任务保存在 `outputs/review_3e4db111fb364b2482ce78a3ed8bca19/`，交付 `outputs/scientific_d14eb036d1314a4ba5618168c3ca627f/report.md` 和同目录 4 页 PDF。约 139 秒的任务事件轨迹中，Lead 派了 FY2025 独立原件、FY2026 原件、跨文件比较三项工作；两份原件都已实际读取，最终报告列出 215,938／130,497 百万美元的收入、102,718／64,089 百万美元的经营现金流及自行计算的 +65.5%／+60.3%。人工逐页查看 PDF，正文、表格、中文字体基本可读。

但这不是全项通过：

- 子 Agent 用 `PDF#page=52` 标引已读原文时，来源校验把页码锚点误当成另一 URL，导致 4 次 `finish` 拒绝；两个子 Agent 最终以 `incomplete` 回传，第三个完成。Lead 利用共享已读证据仍完成交付。已修复 `canonical()`：去掉 URL fragment 后比较文件身份，同时保留 query 和不同文件的区别；回归用例覆盖已读文件页码锚点与真正的另一份文件。
- Data Analyst 想生成两张财年数值柱状图，却被此前仅针对“来源类别行→数值”的新防错规则拒绝；最终报告只有跨文件核验矩阵图，且明确披露柱状图未交付。现已补“原表行＋年份列→数值”的确定性核对，要求原文页段中可见列头；复用**同一份已读证据**的 `scripts/replay-financial-charts.py` 无模型重跑模式已验收 1 张矩阵＋2 张收入/现金流柱状图，图上数字为 130,497／215,938、64,089／102,718。新增数值标签和较短轴标题，视觉检查可读。**这些图尚未进入本次已发布的 4 页 PDF**，不得把局部重放当作完整任务重测。
- 正文的引文是可点击原件链接，邻近文字标注印刷页码，但尚未做到点击后直接打开 PDF 对应页。尾页的参考条目仅显示“来源”，且序号列表在 PDF 中重复显示 `1.`；属交付表达/排版问题，后续与图表一起复验。

这组可复现失败比笼统评价“金融报告质量”更有诊断价值：来源标识的同一性、财报行列配对以及图表实际交付，分别对应不同可测试契约。ClawsGO 的内部模型与工具预算不可见；两端时延也不能直接当性能对比。

### 第二次同指令端到端复测

修复页码锚点与财年柱状图校验后，再以相同请求运行一次（`--max-actions 48`）。过程记录在 `outputs/review_f094ea67c69a40c5980a5bb5cc7ec118/`，交付物在 `outputs/scientific_aeb171a8b0fc4d62aa6430a2ef3c0952/`，PDF 共 7 页。Data Analyst 生成了两张定量柱状图及两张风险矩阵，Writer 将四张图全部写入 PDF；人工检查了关键页面，收入、现金流柱值及年度标注与已读 FY2026 10-K 比较列一致，正文和图表可读。FY2026 子 Agent 的原文页码锚点正常通过 `finish`，表明此前的 URL 身份问题至少在此分支已修复。

这次**仍未达到完整验收**。FY2025 独立年报的在线读取遇到大文件截断／超时与 SEC 403，旧年报分支没有完成；报告如实声明 FY2025 数值只来自 FY2026 年报的比较列，不能把它算作两份独立原文核验。更重要的是，PDF 正文写出“952 亿美元的采购与产能义务规模远超当期经营活动现金流（102,718 百万美元）”。换算后前者为 **95,200 百万美元**，其实低于 102,718 百万美元。引用真实、图值正确，也不能保证跨单位的推断正确。

人工 QA 后新增仅针对金融报告的金额方向校验：对于同一句中两笔明确标注美元单位、且有“高于／低于”等显式比较词的表述，先统一换算成百万美元；如果方向相反，则阻止交付并要求 Writer 修正。单元回归复现了上述原句；直接对本次已存档报告运行校验，能检出该错误；模拟 Writer 的回归测试验证了“首稿不通过→带错误明细请求修稿→修正稿通过”流程。为避免误杀，包含三笔及以上金额的复杂句子不由此规则猜测结论，仍交由人工／证据复核。**这项修复尚未经过新的线上报告全流程验证；保留第二次 PDF 作为缺陷样本，不将其标记为合格产物。**

### 第三次同指令实测与局部恢复

再次以同一 NVIDIA 指令运行 `scripts/smoke-financial-report.py --online-rag --max-actions 64`，原始 Run 在 `outputs/review_8de7e37b3c274352baeb2c64adc5d9cb/`，交付 `outputs/scientific_00e0568f6554449a86ab09f5ad7bba24/`（7 页 PDF）。这一轮约 455 秒、47 次模型调用、2 个调研子任务；FY2026 与 FY2025 的**两份独立 10-K PDF 均已读取**。收入 215,938／130,497、经营现金流 102,718／64,089（均为百万美元）在原件与新年报比较列之间一致；报告把 +65.5%／+60.3% 明确写作自行计算值，页码链接及研究局限进入正文。金额方向错误未在本次报告复现，但不能由一次通过推断该类错误已被完全消除。

原始交付仍未全项通过：Data Analyst 提议把收入与经营现金流置于同一跨原件柱状图，既不满足既有“单指标、共同口径”校验，也没有允许两个独立财报的年份比较，于是最终只保留 4 张定性矩阵。针对这次真实失败，图表校验现允许**同一指标、相同单位、原文行名与年份列均可核对**的跨财年对照；不同指标自动拆成两张图，学术论文跨证据数值比较仍不放行。缓存分析提案对**原始已读证据**的无模型重放，在 `outputs/financial-chart-replay-40c143ed46d34dca82f1053ecf47e6d1/` 得到 2 张定量柱状图与 4 张经分页的来源／风险矩阵，柱值与独立原件一致。补充了财年重复和单位缺失的拒绝用例。

为检查完整交付版式，从原始 Run 的已存 Lead 交接与证据继续执行 Writer／CitationAgent，恢复状态在 `outputs/delivery_recovery/review_c095989c1a314a5292db89fed396673a/recovery.json`，其中明确记录 `authenticated_end_to_end: false`；之后用已通过校验的图表资产重排同一正文，版式 QA 样本在 `outputs/financial-layout-qa/scientific_7d84ca6353d34133a0b569afbd789ab9/`。人工逐页查看了 7 页 PDF：两张数值图可读，来源与风险矩阵未截断；PDF 参考文献将多个 `#page` 链接合并为两份具名 10-K 原件，正文页码链接仍保留。尾页仅有两条参考文献，尚可进一步收紧版式。**这份恢复 PDF 不能替代新版本的完整端到端复测。**

### 第四次完整报告流程复测与排版复核

新图表规则进入运行后，同一指令通过 `scripts/smoke-financial-report.py --online-rag --max-actions 64` 再跑完整流程。Run：`outputs/review_f329f9aa5433467b99809490e46c5f23/`；原始交付：`outputs/scientific_a1cfdb0b30764d60b60921dc693495de/`。约 296 秒、44 次模型调用、2 个并行子 Agent；两份独立 Form 10-K 均已读，Lead、Data Analyst、Writer、CitationAgent 均完成。原始 PDF 有两张定量柱状图与两张风险矩阵（共 4 张），报告数字与上节一致，CitationAgent 最终没有未解决引文缺口。这是**命令行触发的完整报告流程**，不是认证前端的用户路径测试，也不是财务审计。

PDF 逐页 QA 又发现两个实际问题：LaTeX 白名单漏掉安全数学命令 `\div` 与 `\ldots`，公式被印成命令文字；风险章节复制长段英文原文，中文报告可读性下降。已补数学命令及回归测试，并对同一已核验正文做**零模型调用的重排**；同时增强金融写作规范与长英文引述检查。基于本次 Run 的原文、Lead 交接和已校验图表做恢复生成，在 `outputs/delivery_recovery/review_be5ad076126d48ac93868555696839ee/` 留存：第一稿因引述过长被拒，Writer 第二稿改用中文概述；CitationAgent 第一次指出未获支持的句子，定向修订后复核通过。此恢复任务调用模型 14 次，`authenticated_end_to_end: false`，不能将恢复稿当作一次新检索的通过率样本。恢复 PDF 为 6 页，人工逐页检查公式、图表、中文字体、矩阵和两条具名参考文献，未见截断或溢出。

**仍需人工核对的推断**：恢复稿用投资活动现金流出变化解释投资风险，却以“与本次核对的两项指标有关”引入；投资活动与经营活动现金流不是同一指标，不能由同在一张现金流量表便推出对经营活动现金流的影响。该段虽加了“不作因果断言”，口径连接仍偏松，不宜把 CitationAgent 的“引文通过”理解成财务逻辑已审计。下一轮写作应优先选择与用户所问指标有直接机制的风险，或明确它只是另一类现金流科目的旁证。

## 平行能力的架构落点

保留现有入口 `AgentOrchestrator`：金融概念短答仍走 `financial_research` Specialist；正式报告走同一条持久化 Lead → 互补 Subagents → Data Analyst（有图表需求时）→ Writer → CitationAgent → Markdown/PDF 链路。不要复制第二套 Agent 框架。金融与科研的差异放在领域配置和可执行验收条件上：

1. **来源与工具**：金融优先公司 IR、监管披露、交易所与官方统计；已配置的只读金融 MCP 负责发现官方链接，`read` 成功后才登记为已读原文。学术 arXiv 不作为金融默认来源。禁止将搜索摘要升级成证据。
2. **任务拆分**：Lead 依请求派发少重叠的目标，例如原始报表数据、风险及邻近上下文、行业可比口径。子 Agent 回传有来源的发现和缺口；Lead 决定是否补研，不把预设章节直接当派发维度。
3. **财务证据账本（下一步）**：每个数字至少保留实体、独立文件身份、报告期/截止日、发布日期、币种、单位、会计/统计口径、原值、原文 URL、PDF/印刷页位置，以及“原文值/本报告计算值”属性。用户要求独立两份文件时，两个年度必须分别有已读原件；新年报比较列仅是交叉核验，不可冒充旧年报。
4. **计算与图表**：同比由确定性计算复核公式与舍入（尚待实现）。Data Analyst 只能对单位、期间和口径相容的数据作图，图与表必须引用同一证据账本（账本尚待实现）；没做出图要明确交付缺口，不能在正文说“见图”。本轮已增加金融柱状图的原表行标签及年份列头／数值配对校验，防止把 Taiwan 行改写成中国香港或把 FY2025 值错放在 FY2026 柱上；跨独立文件的完整口径账本尚待实现。
5. **交付核对（下一步）**：Writer 按任务选择财报比较或行业研究的结构，避免冗长原文堆砌；CitationAgent 核对数字和风险论断对应的**具体文件及页码**，最后做“独立文件数、关键数据、计算值、表图、限制说明”的任务级验收。引文代理核对不是独立财务审计。

## Anthropic 可以借什么，不能照搬什么

仓库 [anthropics/financial-services](https://github.com/anthropics/financial-services) 的 `sector-overview`、`model-update` 原版已在本项目 vendor 目录保存并附本地工具适配；按需要动态加载，不意味着已接通 FactSet、LSEG 或商业数据。NVIDIA 两份 10-K 核对不属于行业全景，也没有已有财务模型，故不应为了“用了 Anthropic Skill”强行加载这两项。

[Anthropic 的 earnings-analysis Skill](https://github.com/anthropics/financial-services/blob/main/plugins/vertical-plugins/equity-research/skills/earnings-analysis/SKILL.md) 有可复用的**数据日期、具体文件、可点击表图来源、逐项检查**原则；但它默认季度业绩、共识预期、目标价、DOCX 与固定图表数量，不能整体注入当前年度公开资料报告。[market-researcher 角色提示词](https://github.com/anthropics/financial-services/blob/main/plugins/agent-plugins/market-researcher/agents/market-researcher.md) 可参考行业范围、证据来源与报告门槛，但其中商业连接器和 PPTX 产物同样不在 Asteria 当前能力内。

已落实的第一步：写作 Skill 按任务领域过滤，金融报告不再误选学术 `source_priority`；新增本地 `financial_report` 内容规范，承接上述来源归因原则，并扩大到行业研究。金融研究基础规范补充“两份独立财报”的原文约束。金融柱状图新增原文类别／年份列／数值配对校验及回归用例；第二次端到端测试验证了图表进入 PDF，同时发现跨单位比较错误并补上校验，**尚未**因这些改动声称整份报告已通过质量验收。

## 下一次验收

第四次已验证命令行完整报告流程，但仍要从 Asteria **认证前端**走一次用户路径，检查任务状态、下载与中途恢复；还应对上述“投资活动／经营活动现金流”口径松动做针对性写作与人工回归。金额方向校验已通过单元测试及在线报告，但 Writer 在真实金额方向触发时能否自修仍待专项故障注入。若 FY2025 原件不可读，应保留明确缺口，不把 FY2026 比较列冒充独立原件。之后决定财务证据账本与确定性计算层的优先级；不能把单次样本的报告页数当成质量指标。
