# Agentic 协作：有边界的自主派工，而不是固定业务流水线

日期：2026-09-22。状态：第一轮关键路径已实现并通过自动化测试，真实模型验收被余额不足阻断。当前用户优先级：分工覆盖与区分度、coding 向研究角色定向求助、EchoMind 代码结构对齐。

**后续状态更新（同日）**：上述余额不足与“领域并行后续项”属于第一轮记录。当前主入口已提取为 AgentOrchestrator，共享 BaseAgent 已接入，普通只读领域支持主辅角色并行；Reviewer 改为交付时验收。模型现已可用，新结果与剩余差异见 [EchoMind 骨架对齐](echomind-alignment-plan.md)，以该文为当前状态。

## 决策边界

入口只选择能力；Lead 根据观察自主选择直接研究、并行委派、继续调查或结束。Reviewer 独立判断依据和交付条件，运行时强制权限、预算、取消和停止。没有固定的“先论文再代码再实验”步骤；也不强制每次启动多角色。长链路不等于所有步骤都可并行。

## 本轮验收

1. 派发契约：每项有目标 ID、角色、独立调查角度、交付要求和范围排除。未分配目标明确由 Lead 保留，不能因切分遗漏。
2. 派发质量：确定性检查 ID/重复任务，再独立语义检查任务是否重叠、是否真的覆盖所声明目标。失败回给 Lead 修订，未通过不启动子任务。同一来源服务不同问题不视为重复。
3. 并行结果：as_completed 逐项保存和推送结果，记录首项回传/各项耗时/整批耗时；失败不被汇总隐藏，取消保留已到达结果。前端先展示阶段结果，Lead仍在本批完成后综合验收。计划覆盖率不是实测完成率，也不宣称Token级流式输出。
4. 代码协作：已知论文/公式可直接调用论文搜索、下载和页段阅读工具；需要深入综合时才 request_research。请求携带问题、观察和期望答案，研究角色只回答该子问题，再返回原循环。总预算、最多两次求助、相同问题去重、取消传播、禁止研究子角色递归求助。语法检查/diff必须引用本轮真实文件 observation_id；不执行目标代码。
5. 用户视角：提供两组可重复场景，分别检验重复分工纠正、读代码后求助再继续操作；保留替身测试与真实模型测试的区别。

## EchoMind 对照

本地参考：EchoMind/agents/agent_orchestrator.py 的 AgentProfile、BaseAgent._call_llm、run_parallel；core/intent_recognizer.py 的融合识别。

沿用角色契约、工具白名单、有限工具循环、并行后结构化汇总的模式，适配现有 model(system, payload) 接口，不整体复制依赖 Anthropic 的业务层。Asteria 改为 as_completed 逐项回传，每个 Agent 接收不同子目标，独立 Reviewer 不是 ResponseComposer。记录实际复用/适配位置，不能把设计相似写成整包直接运行。

入口已接入 LLM Few-shot、真实 Embedding 与关键词规则三路融合；普通领域主辅并行仍属后续项。保留现有鉴权、知识库范围与持久化 Run，不把入口分类和科研 Lead 的后续派工混为同一个循环。

### 入口适配的具体边界

- 参考 EchoMind 的三路投票接口与角色配置结构，默认权重为 0.7 / 0.2 / 0.1；使用现有配置的 Ollama bge-m3，不把参考源码中的字符 n-gram 降级称为真实 Embedding。
- 向量服务失败时明确标记 local_ngram，并降低该分支权重；LLM 失败直接返回错误，不绕过模型启动工具任务。低置信度或融合结果与语义交付判断冲突时先澄清，前后端均不启动研究任务。
- 严格 LRU（命中移动至末尾）＋300 秒 TTL，最多256项；缓存键包含完整输入、历史、报告、可访问知识库、当前记忆快照、用户、会话、模型配置及模板版本。只缓存判定结果，绝不跨用户复用；静态模板向量可跨用户共享，冷启动并发只编码一次。
- 当前注册10类能力，包含通用对话/知识库问答、3类研究交付及5个领域角色，不再机械沿用旧简历的“8类”。显式指定知识库保持原有权限校验，不强制经过融合。
- 旧研究入口仅接受研究能力；代码、学习、投稿等普通角色须由 Coordinator 执行。独立代码与科研内代码子任务共享同一 coding loop。
- 融合分数是启发式路由依据，不是准确率。六条真实向量探针均匹配预期，只说明配置和向量分支可用；真实 LLM 分工/路由效果仍需模型服务恢复后验收。

## 本轮安全与范围

保留原工作区所有登录/数据库/文件提案改动。代码工具先接公共 GitHub 只读调查与已鉴权的 MCP 文件提案；修改仍需用户批准。实验角色先做到调查、代码分析/提案与定向求助，不开放任意宿主 Shell，不在本机悄悄安装仓库依赖或运行下载代码，不把实验计划当成已经完成实验。GPU 实验执行器及其隔离授权另行接入。

## 实施记录

- 已核查：现有 Lead 委派确实有独立子目标和并行循环，但只有 goal_ids 校验，没有分工语义验收；其他角色只是共享五轮 specialist loop。
- 本轮先增强上述关键路径，之后再根据真实 Trace 调整分工质量，避免为角色数量引入固定流程。
- 已实现：collaboration.py（角色/派发/分工审查）、coding.py（共享循环/定向求助）、repository_tools.py（固定版本只读仓库）、AutonomousReview 集成和独立代码交付验收；两种入口复用同一coding循环。
- 普通工作区coding由原specialist入口进入；科研Lead可选择coding子任务。不增加任意Shell，不能声称已执行实验。
- 真实模型指令已准备，但模型余额不足；普通领域主辅并行和GPU执行器尚未在本轮完成。入口三路融合已在后续增量接入，不把这一轮称为EchoMind全量迁移。
- 后续增量已完成：代码Loop直接复用本轮PaperLibrary与证据预算；Python语法检查、diff预览；并行结果即时持久化与事件推送；Coordinator按会话保存有界progress，支持刷新观察；前端分工/回传顺序/定向求助展示。
- 并发不是让分支同步结束：不依赖的子目标并行，代码角色等待其调研答复时只暂停自己，其他任务照常推进。UI提前展示不表示Lead已经提前验收，也不是完整DAG依赖调度器。
