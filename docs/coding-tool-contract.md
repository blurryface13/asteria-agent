这是模式级适配，不是替换模型供应商或整包复制。没有照搬客服的3轮上限，也没有迁移 Anthropic 专用协议；现有模型适配器和结构化动作保持不变。

**EchoMind 没有在上述代码中实现逐条论断的来源核验，也没有相同工具请求去重规则。**本轮实际片段完成门槛和重复请求保护，是结合其“确定性工具/可观察结果”的原则增加的科研约束，不能说原项目已经直接解决了这些问题。

## 本轮行为变化

1. 同一参数的文件读取等只读/诊断最多执行两次；允许一次重试，但不会连续六次真正读取。改变文件、页码、偏移或查询仍可执行。被拒绝动作有 `executed=false`，不是缓存命中或新证据。
2. 从任务的目标、focus、交付要求识别明确的论文/文献/原文/知识库依赖；此类任务要有实际非空片段，才能 `finish(completed)`。普通代码解释不要求论文证据。
3. 直接阅读和科研求助地位相同，不强制委派。研究子循环把实际 `read_passage / retrieve` 结果随答复回传；只有摘要或链接的 `completed` 会被 Coding 降为 `incomplete`。
4. 每轮提供由运行器构造的 `evidence_index`，包括调用ID、来源、页码/偏移、文本哈希。来源不再从研究摘要中提取后直接信任。索引中的文本/结论仍是不可信外部数据，不授予工具权限。
5. 业务返回失败时，即使函数没有抛异常，仍记录 `success=true, result_success=false`；这样的文件内容不能用于完成校验或生成诊断。`result_success=null` 表示工具未提供明确的业务布尔状态，不自动解释为验证通过。
6. 请求里的 `expected_answer` 是期待交付，不是已知事实；研究角色提示独立核对其中假设，避免迎合预设答案。此项仅增加指导，还未做独立的错误假设真实评测。

边界：目前来源依赖识别是保守的任务词提示，不是完整的语义需求分类；否定/歧义表达可能被保守地要求查证，隐含来源需求也可能漏识别。证据门槛验证“取得过实际片段”，**不能保证片段与每个论断相关或已完成论断级事实审查**。本轮没有接入新的数据库RAG工具、未增加自动执行权限、没有把所有科研分支强制走工作流。

## 回归与真实复测

- 原 BadCase 形态回放：6次同参数读取＋语法有效diff＋声称依据论文完成。实际读取降为2次，其余4次被拒，缺少证据的完成请求被拒，最终 `incomplete`。
- 覆盖普通代码无需查论文、预览/空片段不算证据、直接阅读、携证据求助、只有摘要的求助、业务失败不能作为文件/诊断依据、不同参数可继续、未完成结果显示运行核验提示。
- 全量后端：219通过、5环境跳过（包含原工作区测试，不是本次新增数）；本轮新增12条契约测试，并更新旧求助测试的证据夹具，不用无来源摘要冒充真实片段。
- 真实模型复测：`outputs/coding-research-comparison-74a39ac6d3/summary.json`。使用 `--native-policy`，去掉实验额外的强制路由提示，仍分别限制两组工具范围。两组均通过独立路径检查与生产完成契约：直接组4次调用/9.209秒；委派组7次/20.692秒，求助等待6.672秒。
