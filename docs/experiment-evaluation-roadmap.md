# 自主实验与 Agent 评测路线

2026-09-12 · Codex

本阶段先补受控自主实验，再完善评测。本文是实现决策与指标口径，不是新增功能完成记录。复用现有运行时、项目/对话、Skill、证据与报告交付；保持前端设计、响应式路由和服务端口不变。

## 1. 当前基础与取舍

- 综述采用目标驱动的独立研究循环、动态并行委派、引用追踪和充分性审查；研究任务不按报告章节固定分工。
- SkillSession/catalog 已统一元信息发现与阶段注入。内容指导、格式契约、模板 Profile 和编译工具分开。Skill 不授予执行权限。
- 复现方案有研究/写作指导，但实际远程实验执行尚未完成。不能只补一个 SSH 按钮就认为具备自主实验。
- 项目/对话主数据已存 PostgreSQL；已有评测 EvaluationStore 实际是 JSONL，并非旧 spec 设想的 SQLite。后续运行与评测元数据统一复用 PostgreSQL，JSONL 保留导入导出；大型原文、日志和产物保留文件及哈希索引，不塞进 Redis。
- `evaluation/asteria_executor.py` 当前只支持 basic、multi_agent、multi_agent_perspectives。必须新增当前自主综述/实验运行时的适配，不能用旧 Executor 的成绩代表新版。
- 现有 `outline_coverage` 比较标题，`heuristic_citation_support` 比较 URL，`tool_scores` 比较工具名称集合；它们只能作为诊断信息，不能充当语义覆盖、论断支持或自主规划正确率。

## 2. 大方向一：从复现方案到受控自主实验

### 2.1 决策链路

用户需求 → 主 Agent 澄清目标与成功标准 → 根据论文证据形成实验计划 → 用户授权执行范围 → Experiment Agent 在独立行动循环中检查环境、修改实验代码、提交作业、观察日志、分析结果与有界修正 → 产物归档 → Writer 引用真实实验结果。

“只设计实验”和“执行实验”由意图和授权区分，不要求用户先选任务类型。不预设每个实验必须经过同一工具序列。已有研究 Agent 负责查证据，实验 Agent 负责执行与诊断，审查角色判断实验目标是否达成；不能把自提的额外消融当成用户必做项。

### 2.2 先解决后台执行与权限边界

- PostgreSQL 保存 Run、Attempt、Job、Event、Approval、Artifact 索引及项目/会话归属。Run 是任务，Job 是实际进程，Attempt 是一次实验尝试，三个 ID 不混用。
- 作业由独立 worker 执行，浏览器只订阅事件；关闭页面不隐式取消作业。事件单调序号支持断线补拉，取消是显式操作。
- worker 使用租约和心跳；重启先查询远端 job_id，再决定恢复观察或标记失联，禁止盲目重跑可能仍在执行的训练。提交使用幂等键，未知提交结果需核对，不直接重试。
- 授权绑定 host_id、规范化工作区、代码/命令清单版本、容器镜像、资源/网络范围及预算。扩大权限或超出已批准修改范围时重新审批；不得用一次批准授权未来任意 shell。
- SSH 只作为传输和受控作业启动通道，校验 host key。实验在专用非特权容器执行，限制挂载目录、CPU/GPU、内存、磁盘、超时与出站网络；不挂宿主 Docker socket，不把命令白名单当作 Python 代码沙箱。
- 密钥保存为服务端凭据引用，不进入提示词、仓库和日志。工作区阻止路径穿越及符号链接逃逸。没有满足隔离条件的主机时允许继续设计，不默许降级为宿主无限制执行。
- 本地 API 继续使用 dora；远程实验按项目锁定容器/依赖，不把训练依赖全装进 dora。首次执行目标主机与工作区须由用户配置，本次不预设地址。

### 2.3 工具与 Skill

先实现内部 ToolSchema/处理器，未来需要跨项目共享时再封装 MCP，不为接 MCP 另写一套实验逻辑。

| 能力组 | 拟实现工具 | 边界 |
| --- | --- | --- |
| 环境和文件 | inspect_environment、read_experiment_file、apply_experiment_patch | 只在授权工作区；修改留 diff 与版本 |
| 作业生命周期 | submit_experiment、inspect_job、cancel_job | 提交前校验授权与预算；真实 job_id、退出码和日志游标 |
| 结果处理 | collect_experiment_results、compare_attempts | 从真实文件抽取指标和产物；保留来源与哈希，不接受模型伪造执行结果 |

以上为计划接口，不是本轮新增工具计数。可复用命令以版本化 recipe 声明参数、输入、输出、资源和指标，不以 recipe 强制固定研究顺序。新增实验操作指导 Skill；复用现有方案写作与输出格式 Skill，执行安全检查留在代码层。

### 2.4 功能实现与提交顺序

| 增量 | 实现范围 | 完成边界 |
| --- | --- | --- |
| E1 持久化运行 | Run/Job/Event/Approval 迁移、worker、幂等提交、事件补拉 | 刷新可恢复观察；worker 重启不重复启动；停止请求可追踪 |
| E2 授权执行 | HostProfile/WorkspaceGrant、容器驱动、文件工具、提交/观察/取消 | 用户配置主机后运行一个真实小实验；越界访问被拒绝；授权和日志留存 |
| E3 自主诊断 | 实验 Agent 动作循环、recipe、错误观察、预算与停止判断 | 正常任务完成；故障任务根据日志选择修正或请求用户；超预算正确停下，不伪报成功 |
| E4 可复现交付 | 代码版本、镜像/依赖、参数、数据指纹、种子、指标和产物清单 | 按清单重跑并比较；Writer 区分原文指标、实测结果和建议；沿用报告预览 |

各增量独立提交，先做小规模可解释任务，不以大模型训练作为首个联调任务。E3 的权限内修正允许自主进行，修改模型目标、数据源或资源边界须重新批准。

## 3. 大方向二：统一评测运行、指标与回归

### 3.1 框架与参考工作

运行框架选 [Inspect](https://inspect.aisi.org.uk/)：复用 Dataset/Solver/Scorer 和日志，Asteria 通过 Adapter 执行自身 Agent，不用评测框架的另一套 Agent 替代被测对象。先做依赖兼容检查，只有明确冲突才隔离评测环境，不降级 dora 的应用依赖。

报告质量与引用指标参考 [DeepResearch Bench](https://deepresearch-bench.github.io/) 的 RACE/FACT；科研任务和环境设计参考 [AstaBench](https://github.com/allenai/asta-bench)。本项目自建中文任务和修改后的 rubric 独立命名，不宣传为官方榜单成绩。

### 3.2 系统实现顺序

1. **V1 当前运行时适配与日志**：复用已有 evaluation 对象、路由和页面；接入自主综述，实验准备好后加实验 Adapter。统一代码/model/prompt/Skill/tool/corpus 版本、父子 Agent ID、可见动作与证据、真实 usage。评测脚本提供版本化人工反馈策略，不无条件自动批准任意操作。
2. **V2 任务集和 Scorer**：用 12 个开发样例校准覆盖、论断支持、实验约束和错误归因；规则检查优先，语义项交独立模型裁判并人工抽检。新版分数与旧标题/URL 启发式分数字段区分，旧结果不追溯改名。
3. **V3 对比与重复运行**：冻结任务族、语料、预算、环境和评分版本，完成配对比较与三次独立重复；既有报告页补分项、计数和证据链接，不重做前端设计。
4. **V4 BadCase 与回归**：保留失败输入、来源快照、动作/工具观察、期望约束和复现方式；人工归因与质检后进入下一版本开发/回归集，冻结测试集保持隔离。

任务执行和评分独立记状态；评分失败可以对同一份产物重新评分，不必重新支付研究成本。历史轨迹“重放评分”和新版本“重新执行”明确区分，缓存工具观察也不等于真实环境重跑。

### 3.3 Benchmark 任务集

沿用 spec §17 的目标规模：60 个任务族，24 综述、24 实验、12 动态交互/故障；先做 12 个开发样例，不在本轮构建全量任务。实验先评方案，E4 完成后再加入可执行子集，方案分与执行分分别汇总。

按任务族划分 30 开发、15 验证、15 冻结测试；同论文/主题变体/故障派生任务不得跨 split。样本包括给定来源精读、开放域综述、条件不可比、结论冲突、证据不足、重复补研、实验参数缺失、执行错误、越权指令和用户拒绝。每条任务保存允许行为、必需目标及隐藏评分标准，不固定唯一工具路径。

冻结语料/工具观察轨用于可控对比，真实网络轨用于产品效果；分别报告，不把外网限流掩盖成模型能力差，也不从总体失败率中删掉环境错误。

### 3.4 指标口径

| 指标 | 计算/判定 | 注意事项 |
| --- | --- | --- |
| 任务成功率 | 满足任务必需目标且通过硬约束的运行数 / 全部启动运行数 | 用户中止、环境失败单列归因，同时保留端到端口径 |
| 目标覆盖率 | 有证据支撑的必需目标权重 / 必需目标总权重 | 不按标题数量或 Agent 自扩展方向打分 |
| 引用支持率 | 原文支持的 claim–citation 配对数 / 可判定配对数 | 另报不可判定比例；URL 存在不等于支持；抽样需记录抽样覆盖 |
| 引用覆盖率 | 有充分引用支撑的事实论断数 / 所有需引用的事实论断数 | 与引用数量、可访问率分开 |
| 综合质量 | 方法综合、实验条件可比、局限/空白、可读性分项 rubric | 内容满足即可，不强制独立“局限”章节；盲评并定位证据 |
| 工具可靠性 | Schema 合法率、实际执行成功率、语义正确调用率 | 分母分别是提交调用、执行调用、被审查调用；非期望名称序列匹配 |
| 停止与适应 | 过早结束、无效重复补研、扰动后有效改策的任务比例 | 人工标注充分性检查点；不能拿同一生产审查器当独立标准 |
| 实验方案满足率 | 数据划分、基线、参数、资源、指标和复现约束满足数 / 适用约束数 | 缺失原文信息应明确，不奖励编造超参 |
| 实验执行成功率 | 达到独立产物检查和指标容差的实验运行数 / 启动实验运行数 | 容差按任务预定义；不能以退出码 0 或论文原表数字代替 |
| 重跑一致性 | 清单完整率，以及干净环境重跑指标偏差 | 非确定性任务用预定容差，保存种子和数据版本 |
| 授权安全 | 越界、未批准执行、拒绝后执行、虚构执行的发生数 | 单独硬失败，不允许平均质量分抵消 |
| 可靠性 | 每任务独立运行 3 次的全部成功率、单次成功率 | 三次全成功不是 pass@3；报告计数和任务族区间 |
| 时间与成本 | 活跃执行 p50/p95、人工等待、输入/输出 token、总费用、动作量 | 包含失败成本；无真实 usage 为缺失，不用字符估 token 或费用 |

裁判与生产审查角色分离，固定裁判版本；先用双人标注的开发样例校准，再记录分歧与仲裁。评分器不把隐藏答案泄露给 Agent。零分母报不适用，不默认为满分。

### 3.5 消融与项目收束

- 固定模型、预算、任务、语料和工具，对比旧 workflow 与当前自主链路；不能靠增加预算解释“架构提升”。
- 在线 RAG 开/关；可选内容指导无/自动/用户指定；动态委派启用/禁用，分组对比，不一开始跑完整笛卡尔积。无可选 Skill 仍保留安全政策和输出契约。
- 记录任务完成、引用支持、无效补研、时间和费用的配对变化，先不编写任何提升百分比。
- 四条简历分别对应自主调研、受控实验、评测回归与既有 RAG。达到这些交付边界后以稳定性和评测驱动修正为主，不继续扩张通用办公或股票交易能力。
